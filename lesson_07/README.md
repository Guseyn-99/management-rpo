**ПРАКТИЧЕСКАЯ РАБОТА**

**SWOT-анализ IT-проекта**

**СИТУАЦИЯ 1 · Стартап мобильного приложения**

Команда из 5 человек создаёт сервис заказа еды. Есть опытные разработчики и дизайнер, но нет маркетолога. Конкуренты активно рекламируются, пользователи ждут новых функций.

<p>• Небольшая команда - проще согласовывать решения</p></th>
<th><p><strong>W | СЛАБЫЕ СТОРОНЫ</strong></p>
<p>• Нет специалиста по маркетингу</p>
<p>• Не выстроено профессиональное продвижение</p>
<p>• В маленькой команде ограничены рабочие ресурсы</p></th>

<p>• Выделиться за счёт удобства заказа</p>
<p>• Учесть запросы пользователей при обновлениях</p>
<p>• Запустить пробную версию для сбора отзывов</p></td>
<td><p><strong>T | УГРОЗЫ</strong></p>
<p>• Активная реклама конкурентов</p>
<p>• Пользователи могут предпочесть известные сервисы</p>
<p>• Риск отставания от конкурентов по скорости обновлений</p></td>
</tr>
</tbody>
</table>

**Управленческий вывод**

Использовать опыт разработчиков и дизайнера, чтобы быстро выпустить удобную версию приложения. Сначала наладить продвижение и выбрать самые востребованные функции; с конкуренцией бороться за счёт качества сервиса и обратной связи.

</tr>

**Конкретные меры по снижению рисков**

> • Составить простой маркетинговый план: каналы, бюджет, сроки.
>
> • Выпустить минимальную версию, собирать отзывы и обновлять её по приоритету.

Команда из 10 человек работает по Agile. Сильные графические дизайнеры и разработчики движка; нет опыта с микроплатежами. На рынке появляются новые конкуренты.

<p>• Agile позволяет быстро менять план</p>
<p>• Команда из 10 человек для распределения задач</p></th>

<p>• Нет опыта с микроплатежами</p>
<p>• Сложно заранее оценить риски платёжной функции</p>
<p>• Требуется дополнительное обучение или помощь эксперта</p>

<p>• Проверить интерес аудитории через демоверсию</p></td>
<td><p><strong>T | УГРОЗЫ</strong></p>
<p>• Появление новых игровых платформ</p>
<p>• Быстрое изменение предпочтений игроков</p>
<p>• Высокие требования к удобству и безопасности оплаты</p>

Основной упор сделать на сильную графику и качественную работу игры. Недостаток опыта с микроплатежами закрыть консультацией специалиста и тестированием оплаты.

> • Проверять покупки на тестовых платежах, включая ошибки и возвраты.
>
> • В каждом спринте анализировать отзывы игроков и функции конкурентов.

**СИТУАЦИЯ 15 · Разработка чат-бота для банка**

Команда из 7 человек разрабатывает чат-бота для клиентов банка. Есть эксперты по NLP, но не хватает тестировщиков. Сроки жёсткие, заказчик требует безошибочной работы с финансовыми данными.

<colgroup>
<col style="width: 50%" />
<col style="width: 50%" />
</colgroup>
<thead>
<tr class="header">
<th><p><strong>S | СИЛЬНЫЕ СТОРОНЫ</strong></p>
<p>• В команде есть эксперты по NLP</p>
<p>• Специализация на обработке запросов клиентов</p>
<p>• Команда из 7 человек с распределяемыми ролями</p>
<p>• Понятна основная задача продукта (помощь клиентам)</p></th>
<th><p><strong>W | СЛАБЫЕ СТОРОНЫ</strong></p>
<p>• Недостаточно тестировщиков</p>
<p>• Высокая нагрузка на проверку качества</p>
<p>• Мало времени на исправления перед сдачей</p></th>
</tr>
</thead>
<tbody>
<tr class="odd">
<td><p><strong>O | ВОЗМОЖНОСТИ</strong></p>
<p>• Автоматизировать проверку типовых запросов</p>
<p>• Привлечь банковских специалистов к проверке ответов</p>
<p>• Начать с ограниченного набора безопасных сценариев</p></td>
<td><p><strong>T | УГРОЗЫ</strong></p>
<p>• Жёсткие сроки сдачи</p>
<p>• Высокие требования заказчика к точности</p>
<p>• Риск ошибок при работе с финансовыми данными</p>
<p>• Потеря доверия клиентов при неверных ответах</p></td>
</tr>
</tbody>

**Управленческий вывод**

Использовать знания NLP-экспертов, но не выпускать непроверенные сценарии. Главный приоритет — усилить тестирование и защитить финансовые данные; в первую версию включить только надёжно проверенные функции.

**Конкретные меры по снижению рисков**

> • Автоматизировать тесты типовых и ошибочных запросов; вести список дефектов.
>
> • При сомнительном запросе переводить клиента на оператора и не раскрывать чувствительные данные.
