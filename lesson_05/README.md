**Планирование и контроль в IT-проекте**

**Кейс 1. Чат-бот для поддержки клиентов**

| Что уже есть                     | Что нужно добавить                    |
|----------------------------------|---------------------------------------|
| Определен срок релиза - 6 недель | разбить проект на промежуточные этапы |
| Выбраны технологии               | Оценка рисков                         |
| Распределены задачи              | План тестирования                     |
| Есть цель проекта                | Контрольные точки                     |

**1. Какие виды планирования уже выполнены?**  
Тактическое и оперативное: определены сроки, технологии и задачи.

**2. Какие этапы планирования ещё нужно провести?**  
Установить контрольные точки, сроки отдельных этапов и план тестирования.

**3. Какие виды контроля необходимо внедрить?**  
Текущий, промежуточный и итоговый контроль качества.

**Контроль:** текущий, еженедельный, контроль качества, итоговый перед релизом.

**Рекомендации менеджеру:** разбить проект на этапы, вести доску задач, заранее выделить время на тестирование.

**Кейс 2. Внутренний инструмент аналитики**

| Что есть                    | Что отсутствует              |
|-----------------------------|------------------------------|
| Стратегическое планирование | Тактическое планирование     |
| Общая цель проекта          | Оперативное планирование     |
| Срок - 2 месяца             | Стабильные приоритеты        |
| Команда из 8 человек        | Чёткие сроки и ответственные |

**1. Какие виды планирования пропущены?**  
Тактическое и оперативное. Есть только стратегическое.

**2. Какие этапы планирования нужно добавить?**  
Определить приоритеты, сроки, задачи и ответственных.

**3. Какие виды контроля помогут соблюдать сроки?**  
Текущий контроль, контроль сроков и незавершённых задач.

**Контроль:** выполнение задач, сроки, незавершённые задачи, изменение приоритетов.

**Рекомендации менеджеру:** зафиксировать приоритеты, ограничить количество параллельных задач, регулярно проверять прогресс.

**Кейс 3. Новый модуль в облачном сервисе**

| Выполнено                     | Нужно улучшить                |
|-------------------------------|-------------------------------|
| Готовы технические требования | Планирование спринта          |
| Есть общее направление работы | Распределение нагрузки        |
| Процесс частично формализован | Распределение ответственности |

**1. Какие этапы планирования выполнены, а какие отсутствуют?**  
Технические требования готовы. Нужно улучшить планирование спринтов и распределение задач.

**2. Какие виды контроля нужно усилить?**  
Контроль прогресса, загрузки команды, сроков и качества.

**Контроль:** прогресс спринта, загрузка команды, качество работы, выполнение задач.

**Рекомендации менеджеру:** выяснить причины снижения velocity, перераспределить задачи, решить конфликты, проводить короткие встречи.

**SWOT-анализ**

| Сильные стороны          | Слабые стороны           |
|--------------------------|--------------------------|
| Есть цели и сроки        | Слабый контроль          |
| Команды сформированы     | Частая смена приоритетов |
| Есть техническая база    | Конфликты                |
| Часть задач распределена | Снижение скорости работы |

**Вывод**

Главная проблема во всех кейсах – это то, что недостаточно четкое планирование и контроль. Менеджеру нужно фиксировать приоритеты, разбивать работу на этапы, назначать ответственных и регулярно проверять прогресс.
